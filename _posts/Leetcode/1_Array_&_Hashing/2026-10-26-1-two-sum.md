## Question

You are given an array of integers `nums` and an integer `target`, return indices of the two numbers such that they add up to `target`.

You may assume that each input would have exactly one solution, and you may not use the same element twice.

You can return the answer in any order.

**Example 1:**

> Input: nums = [2,7,11,15], target = 9
>
> Output: [0,1]
>
> Explanation: The sum of nums[0] and nums[1] is 2 + 7 = 9, which equals the target. Therefore, the indices [0, 1] are returned.

**Example 2:**

> Input: nums = [3,2,4], target = 6
>
> Output: [1,2]
>
> Explanation: The sum of nums[1] and nums[2] is 2 + 4 = 6, which equals the target. Therefore, the indices [1, 2] are returned.

**Example 3:**

> Input: nums = [3,3], target = 6
>
> Output: [0,1]
>
> Explanation: The sum of nums[0] and nums[1] is 3 + 3 = 6, which equals the target. Therefore, the indices [0, 1] are returned.

**Constraints:**

- 2 <= nums.length <= 10^4
- -10^9 <= nums[i] <= 10^9
- -10^9 <= target <= 10^9
- Only one valid answer exists.

**Follow-up**: Can you come up with an algorithm that is less than `O(n^2)` time complexity?

## 辨識訊號

- 看到「add up to target」→ 要找一對數字，想到：
  - 暴力解：每一對都試
  - HashMap：夥伴就是 `target - 自己`，直接查
- 看到「not use the same element twice」→ 先查再放，就不會配到自己
- 看到 Follow-up「less than O(n²)」→ 暴力解不夠

---

## 解法 1：Brute Force

### 關鍵提問

1. 最直覺怎麼做？
2. 每一對都試，要試幾次？n 最大 10^4 會不會太慢？

### 思路

1. 拿一個數字，往後找另一個。
2. 從它的下一個開始找，同一個元素就不會用兩次。
3. 加起來等於 target，就回傳兩個 index。

### Pseudo Code

```text
for i = 0 to len(nums) - 1:
    for j = i + 1 to len(nums) - 1:
        if nums[i] + nums[j] == target:
            return (i, j)

return an empty array or list
```

### 程式碼

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        for i in range(len(nums)):
            for j in range(i + 1, len(nums)):
                if nums[i] + nums[j] == target:
                    return [i, j]

        return []
```

### 複雜度

- Time complexity: O(n²)
  - 每一對都試一次，約 n² / 2 對。
- Space complexity: O(1)
  - 只用到兩個 index。

### 瓶頸

- 每固定一個數字，都要往後走一遍才找得到夥伴，找一次是 O(n)。
- 夥伴是誰其實已經知道：`target - 自己`。如果能 O(1) 查到它在不在、在哪個 index，就不用往後走。

## 解法 2：HashMap（Two-pass）

### 關鍵提問

1. 暴力解每個數字都要往後找夥伴。夥伴其實算得出來（`target - 自己`），能不能直接查？
2. 要查「這個數字在不在、在哪」，用什麼裝？key、value 各放什麼？
3. 題目說不能用同一個元素兩次，查到的夥伴會不會就是自己？

### 思路

1. 第一圈把每個數字丟進 Map，key 是數字、value 是 index。
   重複的數字會留最後一個 index，例：`[3, 3]` 變成 `{3: 1}`。
2. 第二圈每個數字算出夥伴，查 Map，O(1)。
3. 查到了**還要確認那個 index 不是自己**，才回傳。
   例：`nums = [3, 2, 4]`、`target = 6`，3 的夥伴也是 3，查到的就是自己。

### Pseudo Code

```text
seen = new empty map (key = number, value = index)

for i = 0 to len(nums) - 1:
    seen[nums[i]] = i

for i = 0 to len(nums) - 1:
    complement = target - nums[i]

    if complement in seen and seen[complement] != i:
        return [i, seen[complement]]

return an empty list
```

### 程式碼

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}

        for i in range(len(nums)):
            seen[nums[i]] = i

        for i in range(len(nums)):
            complement = target - nums[i]

            if complement in seen and seen[complement] != i:
                return [i, seen[complement]]

        return []
```

### 複雜度

- Time complexity: O(n)
  - 走過 `nums` 兩次，每次查 Map、放進 Map 都是 O(1)。
- Space complexity: O(n)
  - Map 要存 n 個數字。

### 瓶頸

- 複雜度已經是 O(n)，但要走兩遍，還要另外判斷夥伴是不是自己。
- 如果一邊走一邊查，而且先查再放，Map 裡只會有前面的數字，就不會配到自己，也只要走一遍。

## 解法 3：HashMap（One-pass）

### 關鍵提問

1. Two-pass 要走兩圈，還要另外檢查是不是自己。查跟放能不能在同一圈做完？
2. 先查再放，還是先放再查？哪一種不會配到自己？

### 思路

1. 每個數字先算出夥伴 `target - 自己`。
2. 用 Map 記看過的數字，key 是數字、value 是 index。
3. 先查夥伴在不在：在就回傳兩個 index；不在才把自己放進去。
4. **先查再放**，查到的一定是前面的數字，不會配到自己。

### Pseudo Code

```text
seen = new empty map (key = number, value = index)

for i = 0 to len(nums) - 1:
    complement = target - nums[i]

    if complement in seen:
        return [seen[complement], i]
    else:
        seen[nums[i]] = i

return an empty list
```

### 程式碼

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}

        for i in range(len(nums)):
            complement = target - nums[i]

            if complement in seen:
                return [seen[complement], i]
            else:
                seen[nums[i]] = i

        return []
```

### 複雜度

- Time complexity: O(n)
  - 走過 `nums` 一次，每次查 Map、放進 Map 都是 O(1)。
- Space complexity: O(n)
  - 最壞情況，Map 要存 n 個數字。

## Abstract

用 pytest 寫測試：`parametrize` 一次跑很多個 case、怎麼讀結果、怎麼挑 case。
LeetCode 練習和工作上的 U-Sandbox 測試都是同一套寫法。

範例用一個跟題目無關的 `add` 示範，環境是 `pytest 9.1.1`、`Python 3.14.8`，輸出都是實際執行的結果。

---

## 最小結構

測試直接寫在 `Solution.py` 裡：

```python
import pytest


class Solution:
    def add(self, a: int, b: int) -> int:
        return a + b


@pytest.mark.parametrize("a, b, expected", [      # ①
    pytest.param(1, 2, 3, id="positive"),        # ②
    pytest.param(-1, 1, 0, id="negative"),
    pytest.param(2, 2, 5, id="wrong_on_purpose"),
])
def test_add(a, b, expected):                    # ③
    result = Solution().add(a, b)                # ④
    assert result == expected                    # ⑤


if __name__ == "__main__":                       # ⑥
    pytest.main([__file__, "-v"])
```

第三個 case 故意寫錯，下面用它示範失敗時的輸出。

---

## 每個部分

### ① `@pytest.mark.parametrize("參數名稱", [case 清單])`

- 開頭的 `@` 是 ==decorator==，寫在函式正上方，替下面的函式加功能。
  這裡的功能是：==用清單裡的每個 case，各執行一次下面的測試函式==。
- 第一個參數是==一個字串==，列出每個 case 包含哪些值，用逗號分開：`"a, b, expected"`。
- 第二個參數是 ==list==，每個元素是一個 case。

### ② `pytest.param(值1, 值2, ..., id="名稱")`

- 值的==個數和順序==要跟 ① 的字串一致：`pytest.param(1, 2, 3)` 就是 `a=1, b=2, expected=3`。
- 值可以是任何型別，list 就直接寫 `[1, 2, 3]`。
- `id="..."` 是這個 case 的名字，會顯示在結果裡：`test_add[positive]`。
- 最後一個 case 後面的逗號可有可無，習慣加上，新增 case 時比較方便。

#### 不寫 id 會怎樣

也可以只寫 tuple，不用 `pytest.param`：

```python
@pytest.mark.parametrize("a, b, expected", [(1, 2, 3), ([1, 2], [3], [1, 2, 3])])
def test_plus(a, b, expected):
    assert a + b == expected
```

```
NoId.py::test_plus[1-2-3] PASSED                                         [ 50%]
NoId.py::test_plus[a1-b1-expected1] PASSED                               [100%]
```

pytest 會自己產生名字：簡單的值直接用 `-` 連起來；list 這類複雜的值，就變成「參數名稱 + 第幾個 case」，例如 `a1-b1-expected1`，看不出在測什麼。
**所以建議都用 `pytest.param` 加上 id。
**

### ③ 測試函式

- 名稱必須是 **`test_` 開頭**，pytest 才會收集。
- 參數名稱要跟 ① 字串裡的名稱==完全一樣==，pytest 依名稱把每個 case 的值傳進來。
- 放在 class ==外面==，貼齊最左邊。

### ④ 呼叫要測的程式

```python
result = Solution().add(a, b)
```

這一行做了兩件事：`Solution()` ==建立物件==，接著馬上呼叫它的 `add`。
等於：

```python
sol = Solution()
result = sol.add(a, b)
```

物件只用一次就寫成一行；同一個物件要呼叫好幾次時，才存成變數。

### ⑤ `assert 條件`

- 條件為 True → 這個 case ==PASSED==。
- 條件為 False → 這個 case ==FAILED==，pytest 會印出兩邊實際的值。

常用寫法：

```python
assert result == expected        # 相等
assert result != expected        # 不相等
assert result is None            # 是 None
assert x in result               # 有包含
assert len(result) == 2          # 長度
```

### ⑥ 按 ▶ 就跑測試

`pytest.main([__file__, "-v"])` 等於在 terminal 打 `pytest 這個檔案 -v`。
包在 `if __name__ == "__main__":` 裡，只有直接執行這個檔案時才會跑。

## 讀結果

`-v` 的完整輸出：

```
collecting ... collected 3 items

Solution.py::test_add[positive] PASSED                                   [ 33%]
Solution.py::test_add[negative] PASSED                                   [ 66%]
Solution.py::test_add[wrong_on_purpose] FAILED                           [100%]

=================================== FAILURES ===================================
__________________________ test_add[wrong_on_purpose] __________________________

a = 2, b = 2, expected = 5

    @pytest.mark.parametrize("a, b, expected", [
        pytest.param(1, 2, 3, id="positive"),
        pytest.param(-1, 1, 0, id="negative"),
        pytest.param(2, 2, 5, id="wrong_on_purpose"),
    ])
    def test_add(a, b, expected):
        result = Solution().add(a, b)
>       assert result == expected
E       assert 4 == 5

Solution.py:16: AssertionError
=========================== short test summary info ============================
FAILED Solution.py::test_add[wrong_on_purpose] - assert 4 == 5
========================= 1 failed, 2 passed in 0.01s ==========================
```

由上往下看：

| 區塊 | 看什麼 |
|------|--------|
| `collected 3 items` | 收集到幾個 case。數量不對，代表 case 沒寫進去或寫錯格式 |
| 每行 `PASSED` / `FAILED` | 每個 case 的結果，括號裡是 id |
| `FAILURES` 區塊 | 每個失敗 case 一段 |
| `a = 2, b = 2, expected = 5` | 這個 case 傳進來的值 |
| `>` 開頭的行 | 失敗在哪一行 |
| `E` 開頭的行 | **實際比較的值**：`assert 4 == 5`，左邊是程式算出來的，右邊是預期 |
| `short test summary info` | 所有失敗的總整理 |
| 最後一行 | 幾個失敗、幾個通過 |

**失敗時先判斷是誰錯**：程式算錯，還是 case 的預期值寫錯？
預期值要自己手算，所以 case 本身也可能寫錯。

一個 case 失敗，其他 case ==還是會繼續跑==，最後一起統計。

## 常用參數

| 參數 | 用途 |
|------|------|
| `-v` | 每個 case 印一行結果 |
| `-q` | 安靜模式，只印失敗和統計 |
| `-x` | 遇到第一個失敗就停 |
| `-k "條件"` | 只跑名稱符合條件的 case |
| `檔案::函式[id]` | 只跑某一個 case |

```sh
pytest Solution.py -q
```
```
=========================== short test summary info ============================
FAILED Solution.py::test_add[wrong_on_purpose] - assert 4 == 5
1 failed, 2 passed in 0.01s
```

```sh
pytest Solution.py -x -q
```
```
!!!!!!!!!!!!!!!!!!!!!!!!!! stopping after 1 failures !!!!!!!!!!!!!!!!!!!!!!!!!!!
1 failed, 2 passed in 0.01s
```

```sh
pytest Solution.py -k "positive or negative" -v
```
```
collecting ... collected 3 items / 1 deselected / 2 selected
Solution.py::test_add[positive] PASSED                                   [ 50%]
Solution.py::test_add[negative] PASSED                                   [100%]
======================= 2 passed, 1 deselected in 0.00s ========================
```

只跑一個 case（有中括號，整串要加引號）：

```sh
pytest "Solution.py::test_add[negative]" -v
```
```
Solution.py::test_add[negative] PASSED                                   [100%]
============================== 1 passed in 0.00s ===============================
```

`-k` 和指定 id 在 case 很多、只想重跑失敗那一個時很好用。
這也是 id 要取得有意義的另一個原因。

## 怎麼挑 case

不要只抄題目的範例，而是問：**什麼樣的輸入可能讓程式出錯？
**

| 方向 | 自問 |
|------|------|
| 題目範例 | 題目給的 Example 先放進去，至少要過 |
| 答案的位置 | 答案在最前面、最後面、中間，都找得到嗎？ |
| 重複的值 | 有一樣的值時，結果還對嗎？ |
| 題目的特殊規則 | 例如「同一個元素不能用兩次」，有沒有 case 會踩到？ |
| 負數、0 | 題目限制允許的話，負數或 0 會不會出問題？ |
| 最小、最大輸入 | 長度是題目允許的最小值時呢？ |

原則：

- ==每個 case 測一件不同的事==。
  兩個 case 測的是同一種情況，就只留一個。
- **id 寫「測什麼」**：`answer_at_end` 比 `case4` 好，失敗時看 id 就知道是哪種情況。
  id 用英文和底線，不要空白。
- **預期值自己手算**：不要先跑程式再把結果抄成預期值，那樣永遠都會通過，等於沒測。

### 回傳順序不固定時怎麼比

題目說「答案可以是任意順序」時，直接用 `==` 比 list 會出問題，因為 list 的比較會看順序：

```python
print([1, 0] == [0, 1], sorted([1, 0]) == sorted([0, 1]))
# → False True
```

兩邊都先排序再比，就跟順序無關。

## 常見錯誤

### 參數名稱跟函式參數對不上

```python
@pytest.mark.parametrize("a, b, expected", [pytest.param(1, 2, 3, id="x")])
def test_m(x, y, expected):
```
```
In Mismatch.py::test_m: function uses no argument 'a'
```

parametrize 宣告了 `a`，函式卻沒有叫 `a` 的參數。

### case 的值個數不對

```python
@pytest.mark.parametrize("a, b, expected", [pytest.param(1, 2, id="x")])
```
```
Count.py::test_c: in "parametrize" the number of names (3):
  ['a', 'b', 'expected']
must be equal to the number of values (2):
  (1, 2)
```

宣告了 3 個名稱，這個 case 只給了 2 個值。

### 其他

| 症狀 | 原因 |
|------|------|
| `NameError: name 'pytest' is not defined` | 檔案最上面沒有 `import pytest` |
| 按 ▶ 沒有任何輸出 | 少了最下面的 `if __name__ == "__main__":` 那段 |
| `ModuleNotFoundError: No module named 'pytest'` | VS Code 選的 interpreter 不是 `.venv` |
| `no tests ran` | 只指定了資料夾，`Solution.py` 不是 `test_` 開頭不會被自動收集，要直接指定檔案 |

## 工作上的 pytest

U-Sandbox 的單元測試也是 pytest，用的就是這篇的寫法：`parametrize`、`id`、`assert`。
執行用的 `src/usandbox/unittest/testusbx.py`，最後兩行跟 ⑥ 是同一個做法，在程式裡呼叫 `pytest.main`：

```python
rc = pytest.main(args=sys.argv[1:] + ["--confcutdir", os.path.dirname(os.path.abspath(__file__))])
sys.exit(rc)
```

它只是在呼叫之前先多做幾件事：設定 `LC_ALL`、把需要的資料夾加進 `sys.path`，再把命令列參數原樣交給 pytest。

==測試要在程式實際執行的環境跑==。
U-Sandbox 的測試需要 `stix2`、`psycopg2`、`lxml`、`objgraph` 等套件，`stix2` 在 Python 3.10 以上無法 import，`conftest.py` 也要求設定 `VAULT_TOKEN`。
所以不能拿 Mac 上 LeetCode 的 venv 來跑，要在 Linux / DDAN 上跑。
語法通用，環境不通用。
